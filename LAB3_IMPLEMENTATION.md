# Лабораторная работа №3 — локальное долговременное хранение данных

## Что реализовано

Для варианта 12 добавлены два локальных хранилища.

### 1. Основная реляционная БД — SQLite

Flutter-реализация использует пакет `sqflite`.

Таблицы:

- `health_entries` — записи дневника состояния;
- `health_entry_symptoms` — симптомы конкретной записи (связь один-ко-многим);
- `lab_reports` — лабораторные исследования;
- `lab_markers` — показатели конкретного исследования (связь один-ко-многим).

Для внешних ключей включен `PRAGMA foreign_keys = ON`, а зависимые записи удаляются каскадно.

Теперь:

- новая запись симптомов сохраняется в SQLite;
- OCR-отчет и все его показатели сохраняются в SQLite;
- после полного закрытия и повторного запуска приложения данные загружаются из БД и не исчезают.

### 2. Вспомогательная нереляционная БД — Realm

В Realm хранится реестр референсных значений:

- уникальный id;
- ключ и название показателя;
- пол (`male`, `female`, `all`);
- минимальный и максимальный возраст;
- нижняя и верхняя граница;
- единица измерения;
- источник/примечание.

При первом запуске Realm заполняется из локального `assets/reference_ranges.json`. JSON используется только как исходный набор для первичной инициализации, после чего записи хранятся в Realm.

Значения в текущем JSON предназначены для учебной демонстрации архитектуры и не должны использоваться как медицинская рекомендация.

## Одноразовая подготовка после копирования патча

Из корня проекта:

```powershell
flutter pub get
dart run realm generate
flutter run
```

Команда `dart run realm generate` создаст:

```text
lib/models/medical_reference.realm.dart
```

Это локальная кодогенерация из зависимости проекта — глобально устанавливать отдельный генератор не требуется.

## Что проверить на Huawei

1. Запустить приложение.
2. На главном экране найти карточку `Хранилища данных`.
3. На первом запуске ожидается примерно:
   - SQLite: 3 записи дневника, 2 исследования;
   - Realm: 7 референсных записей.
4. Добавить новую запись симптомов.
5. Убедиться, что счетчик SQLite увеличился.
6. Полностью закрыть приложение.
7. Запустить снова — новая запись должна остаться.
8. Отсканировать тестовый бланк из лабораторной №2.
9. Полностью закрыть и запустить приложение — отсканированный анализ должен остаться в списке.

Это является главным тестом лабораторной №3: данные должны переживать перезапуск процесса приложения.
